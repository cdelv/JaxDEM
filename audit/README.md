# JaxDEM 1.0 readiness audit

Audited on 2026-09-10 at commit `2598c85f09dbe2a91b8ff43238e85a900600e6eb`, using the working tree. The existing edits to `pyproject.toml` were included when checking typing configuration. Existing untracked simulations, images, and graph reports were excluded from the library review. The initial audit did not change the library; the follow-up below records the requested fixes.

**Recommendation: hold the stable release.** There are reproducible cases of missed interactions, broken rigid-body invariants, non-persistent plasticity, and changes to physics after checkpoint restoration. The implementation has substantial documentation and useful tests, but several component combinations violate the assumptions of their neighbors. Address the shared contracts below before polishing the public API for 1.0.

This is a broad source, numerical, packaging, documentation, and test audit of a 114-file, approximately 40,000-line library. It is not a proof of correctness or a claim that every line and parameter combination has been exercised. The reinforcement-learning environments, geometric construction algorithms, and analysis kernels received less numerical validation than the core solver. Long conservation tests, minimum-dependency installations, multi-device execution, and TPU behavior remain release validation work.

**How to use this checklist**

- **P1:** fix before declaring the affected feature stable. A feature can instead be explicitly excluded from the 1.0 support contract and rejected when selected.
- **P2:** resolve before freezing its API, or document a deliberate limitation and add the corresponding validation.
- **P3:** documentation, maintainability, or evidence improvements.
- **Reproduced** means a small executable probe or existing test demonstrated the issue. **Source-confirmed** means the defect follows directly from the implementation. **Design/validation** items are concerns or missing evidence, not claimed experimental failures.

The `probes_*.py` files print diagnostic results, including expected errors on the audited revision. Run them from this checkout with its dependencies installed, for example `JAX_PLATFORMS=cpu python audit/probes_core.py`. They are diagnostic reproductions, not passing regression tests. Captured outputs are in [evidence](evidence/). Convert the relevant cases to assertions when implementing fixes.

**Follow-up scope and deformable-model usage review — 2026-09-10**

Implementation changes are limited to requested items **06, 08, 18, 25, 28, 29, and 30**. All seven are resolved in local commit `43f1efd`; their original severity labels are retained for traceability. Other findings remain open; reviewing an item's intended usage below does not imply that its implementation was changed.

The [deformable model guide](../examples/deformable_particle_guide.py), [DP construction pipeline](../examples/dp_construction_pipeline.py), and [general construction example](../examples/general_particle_construction.py) attach a bonded-force container to `System`, then use ordinary stepping. The general example documents selecting plastic variants through `dp_plasticity_type` and `dp_tau_s`; it does not prescribe a separate reference-update callback. Repeating this construction through `create_dp_container` on a deformed polygon confirms **01** for edge, perimeter, and bending plasticity: each direct functional update changes its reference, while all three simulation steps retain the original reference. See [the expanded probe](probes_plastic.py) and [follow-up output](evidence/plastic_followup.txt). This is a persistence defect in plastic variants, not evidence that the elastic model's reference state should evolve. No plasticity fix is included in this follow-up.

The examples also narrow the interpretation of **10–12**. DP mesh `elements`, `edges`, and adjacency belong to the bonded model; they are distinct from `State.add_connected_facet` contact geometry. Item **10** therefore does **not** establish broken shared-vertex connectivity in the intended DP workflow. The [clump construction pipeline](../examples/clump_construction_pipeline.py) supplies geometry-derived volume and inertia through `create_ga_state`, avoiding the low-level `add_clump` omissions in **11–12**. DP construction instead assigns each independent node a share of body mass and reference union volume; the volume sum is consistent with that reference-volume convention. Instantaneous deformed volume is a separate, explicitly unsupported quantity in `compute_particle_volume`. These findings should not be read as failures of every higher-level construction route.

**Correctness and persistence blockers**

- [ ] **01 · P1 · Plastic reference-state updates do not survive a simulation step. Reproduced.** [deformable_particle.py](../jaxdem/bonded_forces/deformable_particle.py#L925) assigns `system.bonded_force_model` inside a jitted function that returns only force and torque. That assignment cannot update the caller's system across the JIT boundary. With a fixed edge of length 2, rest length 1, `tau_s=1`, and `dt=0.1`, direct reference updating gives 1.1, but three simulation steps all retain rest length 1 and force magnitude 0.9. **Accept when:** the rest length progresses 1.1, 1.19, 1.271; repeated evaluation alone does not advance physical time; all three plastic variants pass persistence and restart tests. See `probes_plastic.py`.

- [ ] **02 · P1 · Accelerated colliders miss Lees–Edwards contacts. Reproduced.** [cell_list.py](../jaxdem/colliders/cell_list.py#L51) hashes an orthogonal periodic grid without accounting for the shear offset in the neighbor stencil. `MultiCellList` has the same compatibility problem, inherited by the default secondary collider of `NeighborList`. In a 10×10 box, `gamma=0.5`, positions `(1,0.1)` and `(6,9.9)`, and radii 0.2, naive forces are `(0, ±2000)` while all three accelerated paths return zero. **Accept when:** force, energy, and neighbor queries match naive across shear, axis choices, and boundary crossings, or unsupported combinations fail at construction.

- [ ] **03 · P1 · Interaction range is not a shared force/collider/analysis contract. Reproduced.** Default [cell-list sizing](../jaxdem/colliders/cell_list.py#L405) uses contact radii; [Lennard–Jones](../jaxdem/forces/lennardjones.py#L54) reaches `2.5*(Ri+Rj)`. Two unit spheres at x=0.9 and 4.1 have nonzero naive LJ force, but default CellList and MultiCellList give zero. Separately, [Hessian helpers](../jaxdem/utils/dynamical_matrix.py#L115) default to `3*max(rad)`: at separation 3.2 the default Hessian is zero while cutoff 5 gives norm 1.54255. WCA and facet extents also need range accounting. **Accept when:** force models expose conservative search bounds, compositions combine them, and all consumers use or validate them.

- [ ] **04 · P1 · Free-domain minimization can report a false zero-energy minimum. Reproduced.** [minimizer evaluation](../jaxdem/minimizers/routines.py#L88) queries forces without preparing the free domain's bounding box. A newly created system still has the default box. Overlapping unit spheres at `(4,4)` and `(5,4)` yield zero forces, zero steps, and zero energy under CellList/MultiCellList minimization, while naive detects the overlap and takes an optimization step. **Accept when:** domain/search geometry is prepared before every relevant trial evaluation, including trials that move outside previous bounds. See `probes_minimize.py`.

- [ ] **05 · P1 · Neighbor-list validity ignores domain and topology changes. Reproduced for shear.** [_check_and_rebuild](../jaxdem/colliders/neighbor_list.py#L58) checks only particle displacement and build count. Holding positions fixed and changing Lees–Edwards strain from 0 to 0.5 leaves a cached empty list, despite a new contact. Bond exclusions changed after a build can likewise leave newly permitted pairs absent. **Accept when:** geometry/topology changes invalidate the cache through a defined API or version token, including deformation protocols; invalidation preserves valid physical contact history where appropriate.

- [x] **06 · P1 · Langevin noise tears rigid clumps apart. Resolved.** [Langevin](../jaxdem/integrators/langevin.py) now gathers translational noise by `clump_id`, sharing each body sample among its members while retaining the replicated body mass in the covariance. Independent spheres and prescribed fixed velocities are preserved. The original regressions verified common velocities/centers, independent body samples, fixed velocity, and the equilibrium OU variance `k_B*T/body_mass` on CPU and CUDA. Those two tests were subsequently removed at the user's request; the implementation fix remains.

- [ ] **07 · P1 · Cundall–Strack contact velocity omits the clump offset. Reproduced.** [cundall_strack.py](../jaxdem/forces/cundall_strack.py#L165) treats `state.vel` as the sphere-center velocity, then adds only `omega × sphere_contact_arm`. For clumps, `state.vel` is the body COM velocity, so `omega × state._pos_p_rot` is missing. Equivalent contact geometries with the correct member-center velocity give different force components. **Accept when:** a shared contact-velocity helper uses the full COM-to-contact arm and matches analytical rotating-clump cases in 2D and 3D.

- [x] **08 · P1 · Batch size one fails in `System.step`. Resolved.** [System.step](../jaxdem/system.py) now dispatches by layout: `(N,dim)` is unbatched and `(B,N,dim)` is mapped even for `B=1`. Unsupported state ranks and mismatched state/system ranks raise `ValueError` during tracing; no repeated host synchronization is added. [Regressions](../tests/test_step_layout.py) compare every dynamic state/system leaf after three moving-particle Verlet steps for unbatched, B=1, and B=2 runs, and exercise mismatched layouts. CPU and CUDA checks pass.

- [ ] **09 · P1 · Fresh Verlet simulations use uninitialized acceleration. Reproduced.** [step ordering](../jaxdem/system.py#L61) performs the first half-kick and drift before initial forces have been computed. A stationary particle under gravity −10 with `dt=0.1` ends its first step at y=0, vy=−0.5 instead of y=−0.05, vy=−1. No explicit initial-force preparation is enforced by the normal creation/step flow. **Accept when:** provide and use an initialization contract that computes forces once without advancing plastic history, time, or one-shot loads; handle edited/restored states deliberately.

- [ ] **10 · P1 · Connected facets overwrite existing vertex incidence. Reproduced.** [add_connected_facet](../jaxdem/state.py#L2326) stores one `facet_id` and one facet-vertex row per particle. Adding edge `(1,2)` to edge `(0,1)` overwrites vertex 1's old incidence, leaving rows `[(0,1),(1,2),(1,2)]`. This cannot represent both memberships for the shared vertex, especially for flexible-facet force distribution. **Accept when:** separate facet connectivity from particle storage with an incidence representation, or reject sharing until supported; verify force/energy consistency on a connected mesh.

- [ ] **11 · P1 · Clump packing volume is inconsistent with the construction defaults. Reproduced.** [compute_particle_volume](../jaxdem/utils/packing_utils.py#L21) takes a segment maximum, assuming total body volume is replicated on every member. [State.add_clump](../jaxdem/state.py#L1233) defaults to per-sphere volume. Two disjoint unit disks report π rather than 2π, affecting packing fractions and compression/jamming targets. **Accept when:** establish one explicit volume convention, including union volume for overlapping clumps and the intended definition for deformable particles; compare construction routes.

- [ ] **12 · P1 · `add_clump` silently supplies sphere inertia for extended bodies. Reproduced.** [State.add_clump](../jaxdem/state.py#L1383) delegates unspecified inertia to `State.create`, which computes solid-sphere/disk inertia from each radius, without the parallel-axis term. Two unit disks separated by 3 and assigned total body mass 1 get inertia 0.5 instead of 2.75. Different radii can also produce different supposedly replicated inertias. **Accept when:** compute consistent body mass properties from geometry, or require explicit inertia and reject omission; test agreement with the higher-level clump builders.

- [ ] **13 · P1 · Orbax checkpoints lose simulation callbacks. Reproduced.** [System.metadata](../jaxdem/system.py#L899) omits `user_pre_step_actions` and `user_post_step_actions`; these static fields are reconstructed as defaults by [CheckpointLoader](../jaxdem/writers/checkpoints.py#L434). A restored run silently loses driving, control, or boundary protocols. **Accept when:** serialize supported callbacks, reject unrepresentable callbacks before saving, and compare continued trajectories against uninterrupted runs. Leaf equality alone cannot catch this.

- [ ] **14 · P1 · Orbax checkpoints lose component static configuration. Reproduced.** System metadata records domain/integrator types but not their complete construction configuration. A Lees–Edwards domain with `alpha=1,beta=0` restores with indices `(0,1)` while its restored dynamic one-hot vectors still encode `(1,0)`. Its displacement and shift operations then disagree. **Accept when:** round-trip all static fields and constructor-required arguments, including extension classes, and check both metadata and subsequent behavior.

- [ ] **15 · P1 · Energy-triggered neighbor rebuilds leave contact history attached to the wrong pairs. Reproduced.** [NeighborList.compute_potential_energy](../jaxdem/colliders/neighbor_list.py#L688) receives remapped history from `_check_and_rebuild` but omits it from the returned collider replacement. A row that changes neighbor 1 to neighbor 2 retains the previous slot history. **Accept when:** list indices and history are updated atomically through every query path; test a nontrivial history law with pair replacement, removal, and reordering.

- [ ] **16 · P1 · `refresh_collider` drops history and breaks subsequent stepping. Reproduced.** [refresh_collider](../jaxdem/colliders/__init__.py#L285) reconstructs a NeighborList with `history=None` and leaves an explicit placeholder instead of restoring history. `System.step` then fails because the loop carry changes from `None` to an array. **Accept when:** rebuilding receives the force model and initializes a shape-stable history; distinguish resize/reset from a same-topology refresh that should retain physical memory.

- [ ] **17 · P1 · Composed history initialization traces array shapes as values. Reproduced.** [LawCombiner.init_history](../jaxdem/forces/law_combiner.py#L55) and [ForceRouter.init_history](../jaxdem/forces/router.py#L56) are jitted without making `shape` static. A valid history law using `jnp.zeros(shape)` fails when placed in either composition. **Accept when:** array allocation shapes are static or initialization runs outside JIT; test composition with a history-bearing law, not only the built-in stateless laws.

- [x] **18 · P1 for RL · PPO depends on a model-private attribute outside its interface. Resolved.** Removed the mandatory `model._log_std` diagnostic from [PPOTrainer](../jaxdem/rl/trainers/ppo_trainer.py), including the generic `log_std` metric. Training no longer requires an undocumented model field or fabricates a substitute statistic. The existing custom-model bandit and corridor training tests in [test_ppo_math.py](../tests/test_ppo_math.py) both pass. Consumers of the removed diagnostic must obtain model-specific statistics separately.

**Numerical, API, and operational contracts**

- [ ] **19 · P2 · The public stepping path loses static loop bounds and reverse-mode support. Reproduced.** [System.step](../jaxdem/system.py#L702) is jitted with dynamic `n`; a Python `n=2` becomes a tracer before the `isinstance(n,int)` dispatch. The intended unrolled path is bypassed for explicitly supplied counts, and differentiating a simple rollout fails on a dynamic `fori_loop`. **Accept when:** expose distinct static-count and dynamic-count paths, test the supported derivatives, and benchmark compile time and steady-state speed. Do not promise differentiation through every collider without evidence.

- [ ] **20 · P2 · State cache validity depends on mutation style and stack introspection. Reproduced.** [State.__setattr__](../jaxdem/state.py#L264) catches replacement of `q`, but mutating `state.q.w`/`.xyz` leaves `_pos_p_rot` stale. A 180° rotation can leave `state.pos` at +x instead of −x. `__post_init__` also walks Python frames to recognize `dataclasses.replace`, coupling performance to dataclass internals. **Accept when:** make cache-affecting state immutable or provide explicit updates with a documented cache invariant; account for radius/search-radius and box/inverse-box caches too. Benchmark the replacement design.

- [ ] **21 · P2 · Thermostat placement and drift definition are inconsistent. Reproduced for placement; source-confirmed for weighting.** [VelocityVerletRescaling](../jaxdem/integrators/velocity_verlet_rescaling.py#L104) rescales angular velocities before `System` performs the final rotational half-kick, although its docstring promises the terminal temperature equals the target. Its drift subtraction averages member velocities, which is neither body-count invariant nor mass-weighted COM velocity. **Accept when:** define the thermostat stage after all required kicks and the intended drift convention; test unequal masses, unequal clump sizes, torque, and prescribed bodies.

- [ ] **22 · P2 · Minimization conflates conservative energy gradients with total dynamical forces. Source-confirmed.** [minimizer gradients](../jaxdem/minimizers/routines.py#L249) use the negative total force/torque, including velocity-dependent and externally applied forces; these need not be derivatives of the reported potential energy. Stateful force evaluation can also advance history during optimizer trials. The convergence check uses unmasked gradients even for fixed DOFs, and the `System.minimize` wrapper omits `force_tol`. **Accept when:** specify conservative versus driven relaxation, freeze history during objective evaluation, check convergence only on free coordinates, and return a termination reason rather than only step count/energy.

- [ ] **23 · P2 · Neighbor-capacity edge cases can fail or falsely report success. Reproduced/source-confirmed.** [NeighborList.Create](../jaxdem/colliders/neighbor_list.py#L408) computes a packing estimate even when capacity is explicit: zero search radii cause `OverflowError`. It caps explicit capacity using a non-overlap assumption that is not guaranteed during DEM initialization. [Zero-capacity neighbor queries](../jaxdem/colliders/naive.py#L152) return `overflow=False` even when contacts exist. **Accept when:** explicit capacities have predictable semantics, heuristics are labeled estimates, degenerate inputs are supported or rejected clearly, and any truncation sets overflow.

- [ ] **24 · P2 · Validation does not enforce the physical representation contract. Source-confirmed.** [State.is_valid](../jaxdem/state.py#L308) largely checks shapes; it does not validate finite data, material/species bounds, quaternion consistency, positive dynamic mass/inertia, or agreement of replicated clump fields. Several public constructors rely on `assert`, which disappears under `python -O`. [Rollout](../jaxdem/system.py#L679) also casts fractional strides to integers and lacks the documented explicit rank check. **Accept when:** provide clear host-side validation and an optional checked execution mode; keep repeated host checks outside the hot loop. Test invalid values and IDs so JAX's out-of-bounds indexing cannot silently choose a material or law.

- [x] **25 · P2 · Asynchronous writer failures are not observable through completion. Resolved.** [BaseAsyncWriter](../jaxdem/writers/async_base.py) retains worker failures and raises `AsyncWriterError`, including task names and original exceptions, after `block_until_ready` drains the queue or `close` joins the workers. Reported failures are consumed once, so cleanup after catching a completion error is safe. [VTKWriter](../jaxdem/writers/vtk_writer.py) propagates file errors with writer/path context and rejects an active writer that produces no expected file. [Five regressions](../tests/test_async_writer.py) cover aggregation, draining, shutdown, failed/missing VTK output, and successful public save/manifest creation. Lifecycle and cleaning policies in item 26 are unchanged.

- [ ] **26 · P2 · Writer lifecycle and cleaning policies need a stable contract. Source-confirmed/design.** [BaseAsyncWriter](../jaxdem/writers/async_base.py#L67) accepts zero workers, accepts tasks after close, and can then wait forever on unfinished tasks. Its default `clean=True` recursively removes an existing target directory. The [checkpoint cleaning path](../jaxdem/writers/checkpoints.py#L115) uses `ocp.test_utils` and lacks the VTK path's protection against cleaning the working directory/ancestors. **Accept when:** validate worker counts, reject submissions after closure, make cleanup explicitly opt-in for valuable output, and use one tested directory policy with ownership boundaries.

- [ ] **27 · P2 · Strict restoration is not strict about energy functions. Source-confirmed.** [_deserialize_force_functions](../jaxdem/writers/checkpoints.py#L92) catches energy-function import failures and substitutes zero energy even with `strict=True`. This changes diagnostics and minimization without rejecting restoration. [Callable encoding](../jaxdem/utils/serialization.py#L7) also builds a path without proving that decoding returns the same callable; nested functions can be encoded but not restored. **Accept when:** validate round-trip identity at save time and reject any missing required physics in strict mode. Document trusted-input loading and add an explicit schema version/migration policy.

- [x] **28 · P2 for RL · Learning-rate annealing uses the wrong time unit. Resolved.** [PPOTrainer](../jaxdem/rl/trainers/ppo_trainer.py) maps completed optimizer updates to epochs using `num_minibatches // accumulate_n_gradients`, then evaluates the cosine schedule over `num_epochs`. The rate stays constant throughout each epoch, including accumulated updates. [Regressions](../tests/test_ppo_math.py) check within-epoch constancy, epoch boundaries, and continuation with retained optimizer state. Resuming requires the full optimizer state; `start_epoch` alone does not restore schedule progress or optimizer moments.

- [x] **29 · P2 for RL · Gradient accumulation occurs after the optimizer transformation. Resolved.** [PPOTrainer](../jaxdem/rl/trainers/ppo_trainer.py) now wraps clipping and the stateful optimizer in `optax.MultiSteps`, averaging raw gradients before either operation. Accumulation of one uses the direct optimizer chain. [Regressions](../tests/test_ppo_math.py) compare emitted updates, parameters, Adam moments, and counters with an equivalent larger batch across multiple groups of varying vector gradients. The optimizer state layout changes; this follow-up does not migrate optimizer states created by the previous transformation chain.

- [x] **30 · P2 for RL · Prioritized sampling and importance weights do not match. Resolved.** [PPOTrainer](../jaxdem/rl/trainers/ppo_trainer.py) normalizes `priority**alpha + epsilon` by the sum of all such weights, preserving positive support and uniform probabilities for zero priorities. Sampling now uses independent categorical draws with replacement, matching `(S*p)**(-beta)`. A small integer last-occurrence filter makes duplicate segment writes deterministic; value/advantage refresh still operates only on sampled segments. [Regressions](../tests/test_ppo_math.py) cover zero/nonuniform priorities, exact weighted-expectation correction, duplicate writeback, and end-to-end training. Documentation limits the full-correction claim to fixed categorical draws; it does not claim the entire standardized PPO estimator is unbiased.

- [ ] **31 · P2 for RL · Action-space equality ignores parameters. Reproduced.** [BoxSpace.same_as](../jaxdem/rl/action_spaces/box_space.py#L130) reports that boxes `[-1,1]` and `[-20,20]` are the same bijector; [MaxNormSpace](../jaxdem/rl/action_spaces/max_norm_space.py#L160) similarly ignores radius and epsilon. Consumers may use this guarantee to simplify transformed distributions. **Accept when:** equality is conservative and parameter-aware, and invalid width/radius/epsilon combinations are rejected. Add inverse/Jacobian tests near the boundary and origin.

- [ ] **32 · P1 for packaging · Declared Python support is impossible at its lower bound. Source-confirmed.** [pyproject.toml](../pyproject.toml#L10) advertises Python ≥3.10 while requiring JAX ≥0.8.1; [JAX 0.8.1 metadata](https://pypi.org/project/jax/0.8.1/) requires Python ≥3.11. Several plastic model modules also import `typing.Self` without the compatibility fallback used elsewhere. **Accept when:** choose an actual supported Python/JAX matrix, align metadata and docs, and install/test its oldest and newest supported combinations.

- [ ] **33 · P1 for packaging · Package discovery ships unrelated and generated modules. Reproduced.** [setuptools discovery](../pyproject.toml#L51) searches `.` without an include restriction. The built wheel contained 114 `jaxdem` files plus 65 documentation Python files, 32 examples, 18 tests, 10 benchmark files, and a tool module, including `docs/build/html/_downloads/...`. Wheel contents depend on local generated files. `Manifest.in` is empty and is not the conventional case-sensitive `MANIFEST.in`. **Accept when:** explicitly restrict packages to the intended namespaces, build from a clean tree, inspect both wheel and sdist, and smoke-test the installed wheel outside the repository. Include `py.typed` if downstream type checking is part of the support promise.

- [ ] **34 · P1 for release evidence · There is no test CI gate. Source-confirmed.** The only tracked [workflow](../.github/workflows/docs.yml) builds docs. It does not run pytest, type checks, installation tests, or compatibility checks, and its pull-request path filter omits packaging/config-only changes. [conftest.py](../tests/conftest.py#L4) globally enables x64, while [energy-conservation tests](../tests/test_energy_conservation.py#L27) skip unless `--full` is supplied. **Accept when:** require quick CPU tests on PRs, relevant GPU jobs, a float32/float64 matrix, and scheduled/full release validation. Keep fast analytic contact/energy tests separate from expensive trajectory checks.

- [ ] **35 · P2 · Documentation does not pass a strict build. Reproduced.** A clean regenerated API/gallery documentation build with gallery execution disabled produced 1,401 warnings under Sphinx 9.1, including duplicate object descriptions/references and malformed indentation in [NaiveSimulator.create_neighbor_list](../jaxdem/colliders/naive.py#L126). Current CI runs `make html` twice without warnings-as-errors. **Accept when:** fix source errors and duplicate indexing, pin/test a docs toolchain, use a strict build, and execute a curated quickstart/gallery smoke suite. The count is toolchain-specific, not a count of distinct defects; this audit did not execute the complete gallery.

- [ ] **36 · P3 · Published terminology and examples disagree with the implementation. Source-confirmed.** [Naming guidance](../docs/source/contribution_guide/naming_conventions.md) prescribes snake_case methods but custom factory construction requires `Create`; the RL package uses `envWrappers`. Factory examples still use `Factory["Foo"]` although Factory is not generic. `System.interact_same_bond_id` describes equal group IDs, whereas `bond_id` now stores adjacency. The class called [CundallStrackForce](../jaxdem/forces/cundall_strack.py#L70) explicitly implements a stateless dashpot approximation and cannot provide static tangential memory. **Accept when:** choose canonical names and migration aliases, correct executable examples, and name/document physical approximations prominently in the public API.

- [ ] **37 · P2 for performance evidence · Benchmark fixtures use obsolete bond semantics and omit intended populations. Reproduced/source-confirmed.** [benchmarks/base.py](../benchmarks/base.py#L94) passes body labels as `bond_id`; current `State.create` interprets them as vertex indices and symmetrizes them. This creates cross-body bonds instead of within-body exclusions. `create_mixed_state` allocates `N//2` spheres and `N//2` clump members, leaving zero deformable members for even N and one for odd N. Clump fixtures also omit geometry-derived mass properties. **Accept when:** validate fixture topology/body counts, use physically coherent construction, and regenerate affected benchmark baselines.

- [ ] **38 · P2 · Performance claims need correctness and workload gates. Design/validation.** [run_benchmarks.py](../benchmarks/run_benchmarks.py#L84) catches failures and continues without an overall failure status. Repeated calls use the same initial arguments, so some stateful benchmarks can repeatedly measure cold logical state even after JIT warmup. The [README](../README.md) says one trajectory save dispatches frames concurrently, but [VTKWriter._write_frames](../jaxdem/writers/vtk_writer.py#L214) loops serially through frames within a single submitted task. **Accept when:** validate each benchmark result, distinguish compilation/rebuild/amortized steady-state costs, record workload/dtype/device/dependency versions, and measure throughput of complete rollouts plus I/O. Preserve current kernel tuning until a measured alternative wins.

- [ ] **39 · P3 · Analysis caching and chunking have scaling limits that are not enforced. Source-confirmed/design.** [analysis/engine.py](../jaxdem/analysis/engine.py#L30) keeps an unbounded global JIT cache; array kwargs are copied to NumPy and serialized into keys. [build_pairs](../jaxdem/analysis/pairs.py#L38) materializes every pair on the host before device chunking, so `chunk_size` does not bound host pair memory. Empty pair sets also return `{}` rather than the usual kernel output tree. **Accept when:** document the limits, bound/cache-clear compilation state, define empty-output semantics, and test chunked/un-chunked agreement and representative large inputs.

- [ ] **40 · P2 · Core import and optional features are more coupled than the API suggests. Design/source-confirmed.** [jaxdem.__init__](../jaxdem/__init__.py) eagerly imports utils, minimization, and checkpoint infrastructure; `System.create` always constructs a minimizer. Base dependencies include VTK and the broad `orbax` distribution even for a headless force computation. Checkpoint code depends on specific Orbax APIs without a lower bound for that actual component. **Accept when:** choose the supported dependency boundary, depend explicitly on the needed checkpoint distribution/version, provide clear optional-import failures, and smoke-test core-only, I/O, RL, and docs installations. Heavy imports should be justified by measured convenience/performance needs.

- [ ] **41 · P2 · Batch and trajectory semantics vary between public helpers. Source-confirmed/design.** `State` documents arbitrary leading trajectory axes, `System.step` handles at most one batch axis, and [thermal helpers](../jaxdem/utils/thermal.py#L48) call 1D `bincount` directly. A batched State accepted by one public operation is not necessarily accepted by another; helper totals also use different axis conventions. **Accept when:** publish a method-level shape contract and consistently choose single-snapshot kernels plus explicit `vmap` wrappers, or genuine leading-axis support. Cover B=1, heterogeneous material tables, and trajectory reductions in tests.

- [ ] **42 · P1 · Packing and jamming callbacks fail in JAX's default float32 mode. Reproduced.** [scale_to_packing_fraction](../jaxdem/utils/packing_utils.py#L128) declares its callback result as `ShapeDtypeStruct(..., int)`, which denotes a host int64 on this platform even when JAX x64 is disabled. The function immediately raises `ValueError: result_shape_dtypes cannot specify 64-bit types when jax_enable_x64 is disabled`. The same declaration occurs in packing protocols and two jamming routines. **Accept when:** use an explicit supported integer dtype consistently on both sides of the callback, and exercise these public workflows with x64 both disabled and enabled. See `probes_float32.py`.

- [ ] **43 · P1 · Cell-hash overflow checks use the wrong integer limit in float32 mode. Reproduced.** [_grid_params](../jaxdem/colliders/_partition.py#L97) constructs int32 grid/hash arrays when x64 is disabled, but compares total cell count to `jnp.iinfo(int).max`, which is the host int64 limit. A 100,000×100,000 grid reports `overflow=False` despite requiring 10 billion cell hashes, beyond int32 capacity. **Accept when:** derive limits from the actual hash-array dtype, detect overflow before integer products/casts, and test both x64 modes and boundary-sized grids without allocating a dense grid.

- [ ] **44 · P1 · Lees–Edwards wrapping breaks shared clump centers. Reproduced.** [LeesEdwardsDomain.shift](../jaxdem/domains/lees_edwards.py#L189) chooses each periodic image using `state.pos`, then shifts `pos_c` separately for every sphere. Members straddling a boundary receive different body centers. A two-member clump centered at `(5,9.9)` becomes centers `(5,9.9)` and `(0,-0.1)` after wrapping. Ordinary `PeriodicDomain.shift` already uses a shared COM representative. This corrupts wrapped rigid-body output and any state continued after an explicit shift; normal periodic stepping does not itself call `shift`. **Accept when:** choose one image per body and preserve relative coordinates, shared COM, and subsequent dynamics.

- [ ] **45 · P1 for custom minimizers · Static optimizer equality can select the wrong compiled computation. Reproduced.** [CustomGradientTransformation.__eq__](../jaxdem/minimizers/optimizers.py#L116) compares only a short `type_name` and kwargs, ignoring the constructor and captured configuration. Two valid optimizer constructors with the same function name but captured SGD rates 0.1 and 0.2 compare equal as static System fields. After compiling the first, the second also produces update −0.1 instead of −0.2. **Accept when:** static equality/hash describe the actual computation, including callable identity/configuration, and metadata are immutable; verify distinct custom optimizers cannot share an incompatible executable. See `probes_optimizer.py`.

**Architectural work to settle before freezing 1.0**

These are proposed reworks, not instructions to discard the tuned array layout. Introduce them behind the current API where practical, and compare compilation, steady-state throughput, and memory before changing hot paths.

- [ ] **A · Separate model evaluation from model evolution.** Force evaluation should return values and any new physical state explicitly. Plastic flow, contact-history integration, thermostat application, and externally prescribed protocols need named stages with exactly-once semantics. Objective/energy/Hessian evaluation should be able to inspect physics without advancing it. This addresses 01, 09, 15–17, 21–22 and avoids JIT-local mutation being mistaken for persistent state.

- [ ] **B · Make geometry and search capabilities explicit.** A boolean `domain.periodic` is insufficient to describe an orthogonal torus versus a sheared lattice. Define the domain's metric/image search requirements and the force model's maximum interaction reach. A collider should declare compatibility and own a validated cache lifetime. Querying neighbors for forces, Vicsek alignment, LIDAR, and Hessians should have consistent cutoff/capacity semantics; `NeighborList.create_neighbor_list` currently ignores the query's requested cutoff/capacity. This addresses 02–05, 23, 38.

- [ ] **C · Separate body, member, and facet topology logically.** The compact replicated clump representation can remain an execution format, but public construction should produce a validated body topology and mass-property record. Shared facet incidence needs its own connectivity data. Optimization should likewise expose one set of independent coordinates per body rather than implicitly relying on replicated member updates. Document which quantities are body totals, per-member contributions, or physical union measures; centralize COM-to-member/contact kinematics. This addresses 06–07, 10–12, 21, 37, 44.

- [ ] **D · Replace reflective serialization with an explicit versioned schema.** Record complete static configuration, dynamic model state, callables, PRNGs, topology, and units/conventions needed for continuation. Share the schema between Orbax and HDF5 while allowing their storage formats to differ. Check restored evolution, not merely array leaves. Include migration tests and clear support boundaries for custom components. This addresses 13–14, 27, 32–33, 40.

- [ ] **E · Establish one mutation and PyTree contract.** `State` intercepts assignments and inspects stack frames; `System` and domain objects are mutable; other components are frozen. `LawCombiner.laws` is static while `ForceRouter.table` is dynamic, which treats nested parameter arrays differently for batching, differentiation, and serialization. Keep numerical parameters as data, reserve static fields for structure/callables, and define cache-aware update operations. This addresses 17, 19–20, 41, 45 and reduces special cases in checkpoints and factories.

- [ ] **F · Put checked orchestration around fast kernels.** Keep unchecked device loops available. Add host-facing preparation/validation, stable simulation status (overflow, nonfinite state, convergence reason), and bounded rollback/retry where appropriate. A rollout that encountered invalid physics should not become apparently successful just because a later neighbor rebuild clears an overflow flag. Use explicit result objects for minimization/jamming and reliable failure propagation for writers. This addresses 04–05, 22–26, 34, 38.

- [ ] **G · Decide what 1.0 means for the RL subsystem.** PPO, recurrent models, action transforms, and application-specific environments are a substantial second product. Either stabilize them with a separate support/test matrix, or mark them experimental with a narrower compatibility promise. Settle truncation versus termination, agent masks, recurrent reset semantics, optimizer schedules, and the public model diagnostics interface. Move scenario-specific setup toward examples where it does not belong in the library's durable API. This addresses 18, 28–31, 40 without delaying a well-scoped DEM core indefinitely.

**Suggested implementation order**

1. Repair persistence and search correctness: 01–05, 13–17; introduce the minimal contracts from A, B, and D that those fixes require.
2. Repair rigid-body behavior and initialization: 06–12, 20–21, 44; choose the topology and quantity conventions from C and E.
3. Stabilize public execution, optimization, errors, and supported combinations: 19, 22–27, 41, 45, F.
4. Decide RL scope, then resolve 18 and 28–31 if RL is included in the stable promise.
5. Establish CI/install/docs gates, fix benchmark fixtures and default-dtype failures, and measure the corrected implementation: 32–40, 42–43.
6. Publish a release candidate, compatibility/deprecation policy, changelog, support matrix, citation metadata, and versioned documentation; promote only after continuation, physics, packaging, and performance checks pass.
